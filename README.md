# AutoResearch 标注能力包

由专家 Agent（Codex 或 Pi）驱动，复用研究设计、任务实现、实验验证、Agent 迭代、材料交付五类能力，让主要工作留在题目本身。

2.1.0 保留轻量、无状态的能力入口，补充按阶段阅读的规则视图、题目 Git 检查点及三个专家决定：研究合同、锚点冻结、正式双轨启动。只读预检引用已有证据，不要求逐条登记；普通操作、原会话恢复和 QA 后打包不增加审批。既有题目仍用其原版本，不自动迁移。

2.1.1 补充题目可迁移性要求：研究时明确部署条件，阶段 2 静态审阅部署调用链，冻结前确认评分环境适用性。复用既有材料与预检，覆盖小资产随包和大资产外置；具体标准见 [当前规则](rules/README.md)，验证和发布状态见 [RELEASE.md](RELEASE.md)。

2.1.2 对齐 V4 / QA 0.3.10，接入双轨前和最终包格式前检，旧题返修优先格式修正与自查。QA15 资源评估与轨迹内容继续核查；项目方通知范围内的哈希、NOP 缺证及换卡补证只作提示。专家实际 GPU 自选、最终配置 H20；迭代基座保持 2.1.1 的 direct/同容器 worker 行为。具体口径见[当前规则](rules/README.md)，正式发布状态与范围见 [RELEASE.md](RELEASE.md) 及当前验收收据。

该包是可迁移的流程与工具源代码，不替代题目自身的依赖、Docker、Harbor、GPU 或模型服务安装，也不声称完成具体题目的科学验证。正式长程运行须由使用者按题目材料和授权配置后执行；发布验收覆盖工具合同、离线可迁移性及已声明的有界运行，不等于实际题目的 QA 或科学验证。

## 开始使用

向制作 Agent 提供流程包及题目目录，说明本次想做的工作：

> 请读取 `/流程根/START_HERE.md`，处理 `/题目根`。先根据该目录的实际材料确定当前工作，从研究/实现/实验/迭代/交付中选择适用能力；在已授权范围内连续推进。

不必安装插件；也可注册或链接 [autoresearch-workflow](skills/autoresearch-workflow/SKILL.md)。保持完整包的相对布局，勿只复制一个 SKILL.md。新题通常准备题目卡、论文、代码或可核来源即可；现成材料整理、局部返修和打包不必从选题重新开始。

## 环境与资料

- 研究时需可用的 Python 3.11+、Git 及题目材料；到运行时再核 Docker、任务依赖、合法数据及所需 GPU。流程不从零安装宿主环境或自动修改系统安全配置。
- 两条迭代均使用 Codex CLI。当前实测目标为 Codex 0.160.0、Harbor 0.23.0、Compose 2.39.4；不是项目方统一指定版本，也不自动兼容其他版本。实际服务地址、模型参数和外部鉴权路径由使用者初始化；不要继承制作 Agent 的账号或把密钥复制到题面、日志和最终包。公开配置示例在 `model_profiles/`。
- 教程和项目方 QA 原件随包保留，版本、默认口径及按需要求集中在 [rules/README.md](rules/README.md)。不依赖相邻设计目录，不逐题重填来源清单。
- 题目与通用包分开；每题一份简短工作记录即可接续，不是程序运行前置。合理使用 Git 保留代码检查点，排除凭据、数据、模型和运行日志。
- 默认运行包只带当前必要模板，见 [模板说明](templates/README.md)；占位值不能作为任务事实。测试、联调、旧稿和详细维护记录只在源码仓保留，不是新题依赖。

## 迁移到另一台机器

解压对应版本的迁移包后，保持包内相对布局，将入口和实际题目目录交给制作 Agent。作者配置、模型、镜像和运行记录不随包分发；先准备所用软件，再填写本机模型资料、授权与题目资源。具体输入见 [运行说明](docs/runtime.md)。每题不需要执行维护者全库测试。文件名含 `preview` 的包仅用于验证，不是正式发行。

发布状态、实测范围和未验限制见 [RELEASE.md](RELEASE.md)；正式发行状态以当前版本的发布收据为准，历史验收和例外不自动继承。
