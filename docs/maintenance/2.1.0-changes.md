# 2.1.0 变更与验收范围

本版正式发行以 `release/acceptance.json` 的当前版本、`status=released` 和 `release_ready=true` 为准。

## 变化

- 六阶段规则视图从中央矩阵派生，指明当期动作、证据、前置引用和定向复核范围；不建立题目级状态机。
- 题目 Git 安全范围、忽略规则和显式检查点；研究合同、B/R/U 与协议冻结、正式双轨启动三个专家决定绑定既有证据和规则版本。
- `preflight` 只读检查缺证、已有检查/实质审阅和例外。机器通过不替代专家确认；不热停健康轨迹，不要求 QA 后再补历史审批。
- Harbor 产物检查按 Trial 冻结题包的 `/workspace/solution` 声明定位；显式、嵌套、默认及空 destination 可用，非法/缺失/越界路径拒绝，不静默回退。
- 精简迁移包的公共入口验收包含预检和题目 Git/决定读取；测试、设计、运行原件和鉴权不分发。

## 保持不变

科学要求、教程/QA 原件、五类能力、独立 Codex 运行底座、实验/材料/三包接口不变。既有题目没有自动迁移、重训或重新长轨的义务；2.0.x 的维护版须单独决定，不自动建立发布分支。

## 证据边界

P4 的六阶段联调使用合成来源、模拟专家决定、模拟轨迹时长和模拟 QA，只有小型 CPU 实验子进程真实执行；不能用其证明实际科研、独立质检或长轨通过。既有题目在独立副本中只读检查，不修正历史证据。旧实跑能否复用由当前执行源码和原件绑定决定，不能借旧版本豁免完成新版本发布。

本版原生 CPU Harbor 验收已于 2026-10-11 通过：默认 destination 的 NOP 与显式 `solution` 的有效候选、独立 Verifier/artifacts/reward及当前源码绑定，耗时约 93 秒。用户于同日明确豁免本版独立新会话全流程试用并授权发布；该项是未验例外，不是实测通过。既有单轨/GPU 原件仅在当前执行源码一致的范围内复用；详见 [发行说明](../../RELEASE.md)。不自动上传 GitHub。
