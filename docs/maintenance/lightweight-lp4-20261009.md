# LP-4：独立 QA 后直接打包与填表

日期：2026-10-09。依据已确认的轻量打包接口及 LP-4；教程/项目方 QA 原件未变。没有执行真实题目 QA、训练、模型调用、Docker、GPU、发行或上传。

## 实现

- `package`只需最终包、独立 report.json、包外附件目录；可选语义名称、上传字节上限、卷大小和普通 Markdown 概述。不导入 TaskStore、Runtime 或 ExperimentBook，不要求阶段登记、handoff、qa-bind、dispositions、选优账本或手填审批 JSON。
- 共享旧 ZIP 流式写入/读回、分卷和快照工具，旧调用接口仍可用；报告合同依赖从 core 提取为 common。新工具复用完整终稿判定，不另运行 QA 或重新审查方法。
- 三包来自同一指定根；保存 UTF-8、完整目录和 Unix 文件类型/权限，读回核 CRC/字节，超限才分卷并核合并哈希。上传上限不固定封顶 300 MB。源包/报告变化停止；已有目录自动新批次，旧附件不覆盖。
- 报告取证对应沿已有实际依据：目录的官方 inventory、生成时间和内容/权限改动记录，副本的内容/权限比较；已记录明确算法的树摘要，或原 QA ZIP 的 SHA-256 和实际文件。普通源 ZIP 支持隐式目录，不虚称未记录目录权限已验证。目录时间依据不是鉴真，局限在使用说明明确保留；无法确定对应时只报具体缺口，不补台账。
- 输出三份 ZIP/必要分卷、上传说明、SHA256SUMS 和七项中文填表信息；不产生 archives.json、form.json 或状态指针，不修改源包。
- 概述取既有专家材料、教程 annotation 字段或 QA 方法介绍，缺失/长正文不能自动提取时待补，不阻塞合格包压缩。正式结构化 B/R 数值不可被备注覆盖；均值、seed 或已知归一化等明确矛盾停止。试跑文字由真实前期运行总结，不自动编造。

命令与边界集中在 [packaging.md](../packaging.md)；交付 Skill 只链接工具，不重复铺设手续。
