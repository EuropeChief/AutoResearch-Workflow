# 故障和返修：按证据处理

新题先查看本轨的 `runtime status`、`runtime logs`、`runtime timing`，再按实际问题调用 `experiment summarize`、`materials check` 或 `package`。入口只读取明确传入的运行目录和材料目录，不初始化状态账本，也不把另一轨的状态当作本轨结论。

| 现象 | 处理 |
|---|---|
| 规则或来源检查失败 | 运行 `rules check`，回查教程/QA 原件及其哈希；不要手改来源锁或用旧包覆盖当前来源。 |
| 实验协议、分数或证据不一致 | 检查 `experiment summarize` 的协议、切分、seed 和原始逐次结果；科学协议变化时重新审查锚点，不能换算拼接不同实验。 |
| 真实预检失败 | 从对应轨迹和作业日志定位模型、权限、评测入口或 GPU 问题；只修受影响路径后重测，不把终端 ping 当作预检通过。 |
| Agent 外部异常 | 保存原始日志和 timing，确认原会话/Goal 是否仍存在；可恢复时用原运行目录 `runtime recover` 后继续原会话，不能新开线程拼接轨迹。明确失去观测的区间要追加 `runtime exclude`，不能按墙钟猜算。 |
| 轨迹缺失或不符 | 以 Agent 自写轨迹 JSONL 和原生会话原件为准，检查字段、轮次、方法摘要和有效时长；可证实的格式错误才能修订，缺失的真实尝试不可补写。 |
| Sandbox 或私有资产边界失败 | 先查看隔离证据和本轨挂载；默认不放宽安全策略。仅在取得本次明确许可后，使用限定的兼容配置重建独立运行，不热改健康会话。 |
| Harbor/NOP/候选试跑失败 | 保存独立 Trial、退出码、Verifier 日志和 reward 原件；区分 NOP、合法候选、候选失败与基础设施异常，不能用 wrapper 成功掩盖 Verifier 失败。 |
| 材料或格式检查失败 | 运行 `materials check`，只从最终材料根组装必要文件；不把含鉴权的运行目录、流程内部账本或无证明作用的日志整体复制进最终包。 |
| QA 报告需返修 | 以当前最终包和独立报告绑定的哈希为准，逐项核对原文与证据；只修改受影响材料，重新交接并由新的独立会话质检，不能沿用旧包报告。 |

历史题目若仍依赖 `task`、`stage` 或旧运行账本，可在确认工作树和范围后使用兼容命令；这些命令不属于新题默认入口，相关状态错误只按历史接口文档处理，不应成为新题的启动前置。

提交前确认：当前包版本与规则来源一致，轨迹有效时长可由原始记录复算，Baseline/Reference 的逐 seed 结果和训练型模型齐全，最终方法可复现，包内没有旧题面解释或与当前分数矛盾的材料。独立报告中的未关闭问题必须如实登记。
