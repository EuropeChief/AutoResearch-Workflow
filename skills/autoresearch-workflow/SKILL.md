先读本 Skill 所在流程包的 [START_HERE.md](../../START_HERE.md)。以入口、本仓来源锁与用户指定任务目录中的 `.autoresearch-flow/` 为准。当前 0.3.0 为开发版，发布状态以本仓 RELEASE.md 为准；启动正式双轨前仍须完成该题的镜像、Harbor、资源、provider 及两组真实预检。不代替最终独立质检；仅支持新任务及同版本恢复，旧状态使用原工具版本。

用户需给流程包和题目根路径；其一缺失时先定位已明确的路径，无法确定再询问。不要从相邻题目或聊天记忆猜任务。本仓 `rules/manifest.json` 已提供权威文件版本、路径和优先级，不要求用户逐题重复填写。新题须有明确初始化授权；已有授权不重复询问。

使用入口说明中的 `task check` 与 `stage status` 恢复当前步骤，再按 [六阶段说明](../../SIX_STAGES.md) 读取当前阶段所需模块；状态与证据只能经统一 CLI 登记。实际科研内容由专家判断，程序检查不替代原文、真实实验或用户冻结确认。

正式轨迹的框架固定为 Codex，专家宿主可以是 Codex 或 Pi。沿用集中模型 TOML 与鉴权引用；原始日志只用于核查，最终轨迹以迭代 Agent 自写的 JSONL 为主输入。两轨默认各自 ≥10h 净有效；在 runtime prepare 前按 [时长政策](../../OP03_DURATION.md) 确认非训练短迭代资格时可冻结为各 ≥7h，后续须核闭环和干净重跑，不能事后降门槛。独立真实迭代，外部异常可原会话续跑，最终无提升不单独判失败。

最终包由用户在独立新会话运行 QA；当前专家处理报告、返修与重包。只用最终包作为 QA 取证边界，不引用制作会话结论替代包内证据。

本 Skill 只保留路由，具体命令、模板和规则集中维护在流程包。安装时让宿主加载本目录或保持到它的链接；若复制，需保留完整流程包和这些相对链接。也可在 Codex/Pi 中直接提供本文件路径使用。

QA 路由以本仓锁定原件与 `rules show` 为准：旧 QA 口头豁免撤销，QA15 按当前 Skill 固定跳过；只接收当前 schema 4 报告。H06 静态 not_run 不能替代教程端到端自验。交付前检查 workspace 可见性清单与实际镜像证据。
