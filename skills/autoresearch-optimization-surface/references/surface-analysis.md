# 优化面分析要点

以下问题用于帮助比较方向，按题目需要取用；结论与后续验证采用当前流程。

- **方法空间**：定位可改文件、函数和语义，给出算法、结构或计算图可以怎样改变的具体例子。Baseline 与 Reference 候选之间有什么机制差异？
- **接口与固定因素**：哪些输入、数据、预算及评测逻辑固定？方法能否由清晰接口承载，是否依赖专家手工选择或不可用的资产？
- **指标与复算**：主指标如何由真实运行独立计算？质量、速度、显存或稳定性分别是优化目标还是约束？
- **合理对照**：Baseline 的来源、实现与预算能否解释？哪些问题尚需训练或基础方法对照才能判断？候选提出不代表正式冻结。
- **改善与噪声**：Reference 候选为什么可能有效？已有成对结果是否支持改善？随机性、收益不足或质量退化需要哪个最小实验区分？正式判据采用任务协议。
- **资源与部署**：估算单次运行及重复评测成本，定位数据、工具、GPU 和目标 Harness 的可用性问题；复用现有验证结果，避免为每个候选重复构建整套环境。
- **证据与退出条件**：引用论文、代码入口和已有实验；说明哪些事实会推翻推荐，以及届时是调整协议、改变机制还是放弃方向。

可推荐一个方向，并在有实际价值时保留最多两个备选。比较应围绕真实代码与证据，不以表格填写完整代替可行性判断。
