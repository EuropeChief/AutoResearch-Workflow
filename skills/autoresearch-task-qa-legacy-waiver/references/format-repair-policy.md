# 旧题完整逐项质检与历史豁免政策

版本：v0.3.10-standard-waiver.5，2026-10-23。本文件是指定旧批次的最终适用政策。**三门控、QA01–QA21、H01–H06、已有正式跑分和双轨内容全部保留；逐项审阅后，再逐原因豁免。**本版不仅保留32项名称，还恢复原v0.3.10结构化静态审查流程；原脚本与参考规范保持原样，先保留原标准结果，再增加豁免。F七项只是补充前检，不能替代原检查。

## 原标准流程与NOP全部保留

默认入口先实际调用原 `audit_task.py` 的静态审阅，按原 `review.json` 保留资源估算、有效时长、轨迹来源/行为/分数、八字段、四项指纹、Harbor路径/Hidden/artifacts及NOP证据校验。原标准结果及细项必须写入报告，不能只把原脚本放在包里而未调用，也不能用32行泛化文字冒充全部细项已审。

NOP原检查不能豁免掉：同Trial的config/result/reward/log、两处nop身份、separate、sandbox相同的反证、结束时间/异常、reward优先级及数值一致、日志非空、当前版本关联和分支覆盖都实际检查。有材料要读，没有材料保留原fail/not_run，再对获准旧批次缺NOP或迁移后未重跑的具体缺口豁免。已有坏记录不变成成功记录；缺提交早退不证明完整Hidden。0分不是单独失败依据，不新增强制哈希，不自动发起NOP运行。

## 为什么 .3.1 明显变快

.3.1 主入口将 G01–G03 和历史 QA18 内容审阅排除，工具仅凭F01–F07形成PASS，专家通过说明也固定为一行。因此快可能来自审查范围减少，不能称为同等覆盖的提效。耗时本身不能证明实际漏读哪份材料；应核查报告和底稿中的实际阅读、复算与逐项结果。

本版恢复完整检查内容，不通过人为等待凑时间。原“免新证明/免补跑”不撤销，不能再次要求专家重做历史研究。

原[21项表](implementation-policy.md)、[三门控](research-quality.md)、[Harbor六项](harbor-harness.md)是逐项内容清单；本表只界定历史豁免，不用本表取代那些逐项检查。QA07/QA08仍只审题面泄露；构建/当前私有可见性由F/H审，历史轨迹内容由QA18及两轨审阅承接。普通联网/依赖下载不直接等于作弊。

大JSON、数组、JSONL是合法载体，不是免读理由。质检员应换用有界/流式读取、按run定位并交叉核对全部相关方法与结果；未读完不得记完成。无法读取和确认不存在是不同事实，工具限制不升级为作者缺陷。

## 逐原因豁免白名单

白名单只作用于某项中的具体finding，不直接把整条QA/H/G变成通过。每个finding保留原始事实、证据和原判；填写具体豁免依据，不能只写“旧题已豁免”。同项其他未豁免问题继续生效。例如QA18同时有旧时间字段缺失和另一题轨迹，前者可获免，后者仍须保留失败，不能把整项涂成通过。

| reason code | 可关联检查 | 可免什么 |
| --- | --- | --- |
| legacy_nop_or_current_trial_gap | H06，向QA17派生 | 二期无NOP或格式返修后未重跑当前Trial。 |
| legacy_trajectory_schema_gap | QA18、QA21、两轨 | 旧两字段/null时间/旧status等新增schema差异；不免内容阅读。 |
| legacy_task_binding_migration | QA21 | 仅旧研究与当前格式返修包之间的hash/版本绑定迁移，不补造历史绑定；不能豁免历史研究A与B之间实质不同的任务条件。 |
| legacy_runtime_proof_gap | QA18、两轨 | 最高档、启动和独立输出等新版证明缺口；不免已有证据确认的真造假/冒充独立轨迹。 |
| legacy_research_duration_gap | QA16、两轨 | 本轮已授权的历史时长或有效时长证明差异；已有时长仍读且按真实口径记录。 |
| legacy_hardware_record_difference | QA15、QA18、两轨 | 历史卡型、内存与返修配置不同；不把旧结果改成新硬件实测，不豁免G02实质预算不公平。 |
| legacy_target_resource_evidence_gap | QA15 | 新资源估算/证明欠缺；当前明确超限或不支持配置不免。 |
| legacy_new_validation_dependency | G03、QA03、QA13 | 原有效结果迁到新环境/新格式后的复验欠缺；原数值、协议、质量门和正式B/R实错不免。 |
| platform_image_preparation_pending | H03、H05 | 有有效构建/源镜像方案，内部镜像tag/选择由字节侧准备。 |
| platform_execution_verification_pending | H03、H05、H06 | 实际启动、解释器、root/seccomp、当前sandbox/移交的运行验证；不免明确静态路径/依赖/入口错误。 |
| unsupported_network_policy_transition | QA05、H02 | 删除不支持的禁网/白名单后，新联网/查表防护尚未落实；当前仍填不支持字段、直接Hidden暴露等独立实错不免。 |
| historical_agent_runtime_finding | QA18、H03、两轨 | 历史Agent违约的新增追责与补跑义务；原invalid保留。不能用于豁免两次研究本身不同的Prompt/反馈/IPC或只读条件；当前作者交付实错与正式B/R失效不免。 |

历史Agent行为finding保留 `classification`、`certainty`、`score_effect` 与其依据、`formal_br_affected`。已确认泄漏/作弊仍记invalid，不能用none抹掉；仅历史运行策略差异且有据无计分影响时可保留原分数状态并记none，不强迫降为unverified。formal_br_affected=false表示本次已审现有作者正式B/R，未把已污染Agent分数当正证，不要求新增污染排除/物理隔离认证。

两轨条件对比按[可比性规则](trajectory-comparability.md)完成。`identical_prompt=false` 是需解释的反证，不凭布尔值直接判失败；读实际差异后，纯文字等价可接受，影响任务/反馈/权限的实质变化使QA18失败。缺新版hash不等于已有差异可忽略；两轨各自分数是否有效和同条件可比是不同结论，不能因此自动宣布作弊或使全部正式B/R无效。

QA17不能整行申请豁免：由H01–H06逐原因结果派生。不得以白名单理由覆盖当前F自动确定的错误。不得以新旧版本不同、旧报告PASS或题包自称，替代实际审阅。

## 原发现与豁免的关联

原`review.json`仍按原流程审全部内容；包装层会生成原标准发现清单及`standard_resolution_template.json`。质检员在内部`legacy_review.json.standard_resolutions`逐条关联具体原发现、已有证据与对应finding，选择保留原失败、按白名单豁免，或用已读材料解决具体manual。原确定失败不能凭泛化手填pass消失；NOP/资源/轨迹/指纹等详细数据同时保留。新增字段仅属内部审核底稿。

合法旧日志载体或工具读取限制应由质检方使用现有材料解决，不能自动转成专家补跑/补字段；任何解决只能针对具体读取/载体问题，不能跳过其余未审组件或掩盖实际无效记录。

## 审核底稿与完成条件

默认入口 `scripts/audit_standard_with_waivers.py`：先实际执行原版标准检查，再按已有底稿逐原因处理。`audit_legacy_task.py`仅是豁免层内容底稿聚合器，不能独立代替原标准检查。底稿是质检员内部工作，不是专家新必交材料：

- 保留F01–F07的 `checks`、当前task定位与可选路径解释。
- `overview`：优化面/实际可改与固定对象、指标与质量门、Baseline/Reference实际方法、全部正式成对数值及引用。
- `content_gates`：G01–G03各一次；G02的 `dimensions` 保留训练充分性、方法代表性、预算可比性、实现正确性、选择完整性五维事实与证据；G03补原协议和锚点的 `assessment` 供工具复算。
- `items21`：QA01–QA21恰好各一次；`harbor6`：H01–H06恰好各一次。
- `trajectory_content_review.trajectories`：两条实际轨迹，各有本题身份、方法与演进摘要、最终结果、成绩采用范围和实际阅读来源；另有内部 `comparability`，写明两次研究实际条件的比较结果、具体差异/影响及证据，不能以“独立运行”替代比较。

各完整项保留 `review_complete`、`observed_status`、`summary`、`evidence`、`findings`。发现逐个写 `kind`、证据、是否豁免及原因，实质返修写具体修复与验收依据。初始模板未完成，不得默认填pass。G03自动数值失败不能被人工pass或legacy_gap覆盖；真缺核心原始证据应记录准确事实，不能靠新增记录豁免抹掉。

审核字段与完整形状以本版生成模板及 `--help` 为准。现有纯数值helper用于复算，不认证原始材料真实性；人工仍须按原文件定位核对提取值和语义。脚本校验覆盖、引用和算术，不声称自动阅读理解全部会话。

不适用仅用于有据确定性评估的QA04/QA19、确无采用配置的H05等工具明确列出的情况。CPU题仍须审QA15资源，不能以不需GPU把整项跳过。

未完成/缺项/引用错误是内部审核流程问题，应由质检方继续处理；不能给整题PASS，也不能一律转为作者补跑。存在已确认实质失败则保留FAIL，其他未完成部分同时列明。不要将质检草稿或工具ERROR当作者退回单发送。
