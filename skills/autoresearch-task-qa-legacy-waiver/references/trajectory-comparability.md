# 两轨独立性与条件可比性（QA18）

本规则补齐旧题完整质检的跨轨比较，保留所有已授权的历史字段、换卡、NOP及新证明豁免。比较由质检员使用已有材料完成，不增加专家必交文件、强制新哈希或补跑。

## 必须分别回答

1. 两条轨迹是否确实存在、属于本题、独立运行，内容/最终方法是否与summary和best一致。
2. 两次研究实际收到的Prompt/任务规则、公开Dev及反馈、允许修改范围、IPC/只读等限制是否实质一致。实际模型可不同；历史硬件迁移按本批政策单列。

读已有轨迹及已交sessions、run_summary、启动材料、两版instruction和版本比较记录。不能只读当前instruction或文件名；也不能只看两条文件存在、独立输出或最终分数。源材料已有 `task_version_comparison.identical_prompt=false` 时，必须定位实际差异并解释，不把它当普通缺hash。

## 判断与豁免边界

| 已有事实 | QA18处理 |
| --- | --- |
| 标点、排版、同义修正；输入输出、反馈、可操作范围等语义等价 | 比较后可接受，列出差异及等价依据；不能只因字节/hash不同判失败。 |
| A研究结束后改了失败反馈、IPC/只读权限、可改范围、评分/Dev口径，再给B研究 | 已确认的实质条件差异，QA18保留FAIL，说明具体差异及对可比性的影响；“两轨独立”可以同时成立。 |
| 旧研究与本轮格式返修包的目录、Docker或字段发生迁移 | 按QA21的legacy_task_binding_migration等具体缺口豁免；这不证明历史A/B同条件，也不覆盖已有实质差异。 |
| 历史探索内存/卡型不同，属于已授权迁移差异且已有相应最终结果依据 | 如实列资源不同，使用legacy_resource_difference并单列原硬件豁免；不可冒称资源完全相同，也不把已知差异写成资料不足。 |
| 缺新版hash、缺启动证明，但已有记录没有确认的实质反证 | 如实写可证明范围与历史证据缺口，按已授权原因处理；不得伪称已证明相同，不能新增补跑义务。 |
| 已有差异记录与审核底稿“条件相同”矛盾 | 由质检员继续读原材料并纠正底稿，不得凭格式全过或泛化摘要出总PASS。 |

`legacy_trajectory_schema_gap`、`legacy_task_binding_migration`、`legacy_runtime_proof_gap` 和 `historical_agent_runtime_finding` 都不能覆盖已经确认的两次研究任务条件实质不同。历史运行中Agent的行为/策略追责与出题时给两组不同任务条件，必须分开归因。

两轨条件不同不自动等于作弊，也不自动使各自成绩invalid；报告只禁止把它们当同条件研究对照。正式Baseline/Reference只有实际采用受影响协议或成绩时，才在G02/G03、QA03/13另列具体影响，不机械连带失败。

## 底稿与对外说明

内部 `trajectory_content_review.comparability` 使用本版工具模板：已完成比较、结果类别、内容摘要、已有证据、已审六维prompt/task/dev/feedback/constraints/resources及各项差异/影响。结果区分same_conditions、editorial_only、legacy_resource_difference、substantive_difference和historical_evidence_gap；文字修正与已授权资源差异可以同时列明。可比性未审不是专家缺文件或必须重跑；质检员须先完成已有材料审阅。

报告必须同时列格式子结论和完整总判。例如：F01–F07通过；QA18两轨独立，但失败反馈和IPC/只读限制存在实质差异，条件可比性失败；旧字段/当前版本绑定仍按具体原因豁免，总判FAIL。不得只给“无需当前格式返修”。

整改先定位原两版题面、现有差异说明及已交同条件研究记录。若可用已有证据证明只是文字等价，据实纠正；若确有实质差异，保留不满足同条件要求的结论，不将本轮改写当前instruction当作追溯修复，不在本批政策下自动要求专家重跑。如需额外豁免，必须由项目另行明确，不能由Skill自行添加。
