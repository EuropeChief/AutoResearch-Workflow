# 题面与接口设计要点

以下问题帮助把研究方向转化为可执行任务，按题目需要取用；正式目录、字段、评测与证据要求以当前教程、QA Skill 和已冻结任务合同为准。

- **可修改接口**：Agent 修改哪些文件、函数和语义？合法方法族能否通过该接口实现？固定面是否限制了真正的方法改进？
- **输入输出**：输入数据怎样取得，输出代码或模型放在哪里，调用方式是什么？评分入口实际读取哪些产物，怎样区分完成、失败与陈旧结果？
- **预算与质量**：运行时间、资源和产物限制能否由实现执行？主指标方向是否清楚，其他质量指标属于目标还是约束？
- **Starter 与对照**：Starter 能否朴素、完整地运行？正式 Baseline 为什么具有代表性，Reference 候选带来什么方法差异？验证不足的部分保持为待验证假设。
- **评分链路**：可信评分器怎样运行候选并独立计算结果？Public/Dev 与最终评分怎样对齐接口与约束？B/R 使用的协议、重复与聚合口径是否清楚？
- **题面披露**：题面提供求解所需的接口和可用工具，是否同时泄露了参考方法、答案、Hidden 材料或作者本机路径？
- **构建与可见性**：Docker context、COPY、工作目录、产物移交和独立 Verifier 的实际调用是否能形成完整链路？隔离设计采用当前流程允许且能满足题目边界的实现。
- **证据产生位置**：哪些现有步骤生成源码、配置、seed、日志、结果及必要模型？复用当前流程已有记录方式，不另建账本或要求额外报告。

先完成清晰可运行的任务草案，再用当前流程的实验与审查修正它；不用设计文档中的预期分数代替实测结果。
