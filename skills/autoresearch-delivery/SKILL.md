# 材料与交付

输入是用户指定的当前源码/证据、目标提交包，以及本次要整理、修复还是打包。目录不明确就核对，不能凭名字选旧包；无需初始化题目状态或实验账本。

材料整理的阶段 6 入口、`independent_qa` 前与退出使用[阶段预检](../../docs/preflight.md)核相关证据；QA 前不要求已有 QA 通过报告或压缩包。只做已通过 QA 的三包压缩时直接打包，不追加阶段审批，题目决定/预检输入不放入最终包。

## 整理与格式核对

- 以 Agent 自写记录整理两份 `{"rounds": [...]}` JSON，核八字段、真实方法演进、分数方向和最佳标记。事实支持的格式/摘要可修正，保留原始输入；不要用日志重新编造方法、分数或时长。[轨迹](../../rules/README.md#m09)
- 依[三目录与说明](../../rules/README.md#m12)、[具体格式](../../rules/README.md#c07)组装；核唯一最终源码、同协议复验、全部 B/R 原始证据、模型重载、NOP 及净时长取证。最终包内能追到说明所引用的必要证据，不能依赖包外旧目录。[训练证据](../../rules/README.md#m11)
- 重点核 JSON 根结构/字段/类型、seed/role/哈希/路径、题目身份和数值口径，检查题面/源码/说明/轨迹是否矛盾或残留旧内容。必要额外材料留正确位置；流程审批、阶段账本、返修前后对比不进包，只留当前正确交付及不能抹去的真实研究事实。
- 核最终题包与已审部署材料一致；入口、worker、镜像、provider、资产或评分条件有相关变化时，定向复核 [C05/C06](../../rules/README.md#c05) 及 [M03/M04](../../rules/README.md#m03)。外置资产按规则保留包内取得/身份/校验说明，不因外置省略必要证据，也不因历史绝对路径改写原件。

使用[独立材料工具](../../docs/materials.md)处理需要的部分：materials trajectory 整理自写记录，materials assemble 按实际来源组包，materials check 只读指定最终包。已有合格材料直接复用。工具输出精确位置与待实质审阅项；格式通过不等于 QA 通过，不为了补程序字段编造轨迹、时长或科研结论。

## 独立 QA 与返修

把确定的最终包路径交给用户，在新的独立会话使用项目方 [autoresearch-task-qa](../autoresearch-task-qa/SKILL.md)。制作会话不替代此检查，QA 只在该包内取证。[QA 边界](../../rules/README.md#m13)

收到报告先确认是已完成语义复核的终稿，不是收集器初稿；检查失败项、依据、建议和最小验收条件。修复实际问题并核受影响部分；影响结论的新包再交独立 QA，直至全部适用项通过。不盲从错误建议，规则冲突先回查当前原件；不把旧 PASS 移植到不对应的新包。

## QA 后直接交付

使用[直接打包工具](../../docs/packaging.md)：一次 package 调用只需最终包、独立 report.json 和包外附件目录，自动三包、分卷核验及填表；已有目录自动生成新结果子目录。缺概述可用普通 Markdown 备注；不为打包重训、重做 QA 或补登记。

1. 核完整独立报告对应当前 `package_root`；指定包外 `output_dir`，不补 qa_bind、handoff、disposition 或阶段关闭手续。
2. 从同一个最终包压缩三个范围：完整提交包、其中的 `workspace/harbor_task/`、`optimization_evidence/`。默认语义名称不加题号；ZIP 保留 UTF-8 名称及必要权限，超过上传上限才分卷。上限和分卷默认值见[交付约定](../../rules/README.md#m13)。
3. 在压缩输出目录写中文七项填表信息：研究子方向、优化面介绍、Baseline 描述/分数、Reference 描述/分数、小规模试跑结论。最后一项从双轨前期真实运行总结，不虚构单独试跑。缺信息据实待补，不编造，也不阻塞已满足条件的压缩。

只做包外压缩/填表不要求重跑研究或独立 QA；源包发生会影响结论的变化时先处理对应核验。产物是最新正确提交包、三个附件和填表文件，不再增加一套流程验收报告。
