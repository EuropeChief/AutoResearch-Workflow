# AutoResearch 提交包格式前检

独立脚本 `check_package.py`，版本 **v1.2.1**。用于返修后的**格式及静态部署配置前检**，检查文件、目录和能从配置确定的错误。只需 Python 3.11 或更高版本及标准库，无需 Skill、模型资源、Docker 或其他 Python 包。脚本只读检查本地目录、ZIP、TAR/TAR.GZ，不上传文件，不运行提交代码，不拉取或构建镜像。

## 前检尺度与后续流程

- **ERROR 阻断**：标准明确、静态依据足够，例如缺正式任务文件、TOML 损坏、缺镜像/构建来源、正式目录含 Compose、缺 separate、明确不支持的资源或约束、确定的 COPY 缺源及提交物路径不覆盖。
- **WARN 提醒，不阻断**：历史构建上下文、动态脚本、未确认执行的 Python 路径线索、镜像可用性及证据内容等，留后续核对。不按固定 Hidden 目录名、示例模型名或必须两个不同镜像退回。
- **检查未完成（退出码 3）**：输入不可读取、不支持的归档或超出工具读取预算；不算通过，也不作为平台格式不合格。task.toml 的 2 MiB 文本预算属于工具限制。

流程为：**专家前检并修复 ERROR → 重新上传完整包 → 质检及 AIDP Harbor 实跑 → 正式验收**。脚本通过只表示本次未发现确定的前置阻断项；不代表全部交付材料已齐或完整质检通过。

## 提交格式

返修后重新上传包含三类目录的完整包，不只交 `harbor_task/`、修改文件或补丁。外面可再套一层题目名称目录。

下图是完整交付参考结构；脚本只检查后文列出的子集，不逐项验收图中的所有证据文件。示例内部名称可按标注标准采用可追溯的等价布局。

```text
完整题包/
├── workspace/
│   ├── harbor_task/
│   │   ├── instruction.md           # 非空题面
│   │   ├── task.toml                # separate、镜像/构建、资源、提交物
│   │   ├── environment/             # 必须保留的 Agent 源码/环境目录
│   │   │   ├── Dockerfile           # 采用该构建分支时提供
│   │   │   ├── starter/             # 按实际需要
│   │   │   ├── public_eval/         # 公开 Dev，目录名可等价
│   │   │   └── public_assets/       # 按实际需要
│   │   ├── tests/                   # 必须保留的 Verifier 源码目录
│   │   │   ├── test.sh              # 标准入口；专用镜像需预置 /tests/test.sh
│   │   │   ├── grader.py            # 评分实现可采用等价模块布局
│   │   │   ├── Dockerfile           # 专用构建时提供，复用镜像可省略
│   │   │   └── hidden_assets/       # 示例名称；也可有依据地生成/安全供给
│   │   └── solution/               # 可选 Oracle，不是容器候选目录
│   └── reference/                  # 专家参考实现，等价位置需说明
├── expert_evidence/
│   ├── 专家作业说明文档.md
│   ├── expert_annotation.json
│   ├── run_summary.json
│   ├── trajectory_a.json            # 两条轨迹可采用可追溯的等价命名
│   ├── trajectory_b.json
│   ├── best_method/                 # 最终方法源码、入口和配置
│   └── nop_trial/                   # 示例名；同一 Trial 配置/结果/reward/日志
└── optimization_evidence/
    ├── 训练证据说明.md               # 非训练题也说明真实评测过程
    ├── baseline_runs/
    │   └── seed_<真实seed>/
    │       ├── result.json
    │       ├── run.log
    │       └── model/              # 仅实际需要模型时提供
    ├── reference_runs/
    │   └── seed_<真实seed>/...
    └── comparison_summary.json
```

完整交付仍按标注文档提供同版本 NOP、两条八字段轨迹、模型与 seed 等证据。**本脚本不审查这些证据的内容或有效性**，也不逐项检查专家证据 Schema；后续由质检 Skill 和 AIDP Harbor 实跑核对。非训练题不补造训练或空模型目录；`public_eval/`、`hidden_assets/` 等内部名字不固定。

以下正式要求继续执行，不因前检放宽而取消：

- 提交一次同版本 NOP 记录：同次 Trial 的 config、result、reward 和日志；平台已有匹配记录可复用。
- 每条轨迹每轮包含 `round`、`policy_name`、`method_summary`、`status`、`score`、`failure_reason`、`retained_best`、`time`。模型组合可调整，实际模型、推理配置和独立运行情况记入运行摘要。
- 公开 Dev 代码和数据须供 Agent 使用；训练与非训练题都须有实际 Hidden 材料，可预置、生成或安全供给。公开共享文件可来自 tests/，不能把整个 tests/ 一概视为禁止给 Agent；私有材料须隔离。
- 每个 sandbox 使用单容器，不能依赖额外工作容器或远端 GPU 工作环境；Agent 与最终 Verifier 仍为独立 sandbox。Verifier 自备评分依赖，不依赖 Agent 临时安装的包、缓存或未移交文件。训练型按标准提交模型及重载证据；非训练型按实际依赖与产物交付，不免除实际需要的模型。

## 本脚本检查什么

| 范围 | 确定检查 | 静态范围之外 |
| --- | --- | --- |
| 完整包 | 三类目录、Harbor 任务根、非空 instruction.md/task.toml、environment/ 与 tests/ 目录 | 证据是否完整有效仍由后续质检核对；参考解未在常见位置找到只提醒 |
| TOML | 语法、已检查字段类型、有效环境/执行配置表、显式 separate | 遗留 resources 表及无法确认的默认值提醒迁移/核对 |
| 镜像来源 | Agent 的实际 docker_image 或 Dockerfile 来源；Verifier 选择优先级、允许复用 Solver 镜像 | 不要求一律有 tests/Dockerfile；镜像可拉取、依赖与预置内容留待实跑 |
| Compose | environment/ 与 tests/ 直属四种 Compose 文件名 | 不递归误伤 docs/examples；不凭未命中证明无额外工作环境 |
| GPU/资源 | GPU 有效配置允许 H20/L20；显式 CPU 题不申请 GPU；数量类型及 ≤8 GPU、≤64 CPU | 实际分配、单轮耗时、换卡影响另核对；混合候选含 H20/L20 不误退 |
| 不支持约束 | 有效环境启动与 Agent/Verifier 执行阶段的 storage_mb、已知禁网/白名单请求 | 本批不接收以磁盘限额为研究或评分必要条件的题目；语义依赖由后续质检核对，删除配置不等于设计已合规 |
| 构建/入口 | COPY/ADD 确定缺源/越界、简单 .dockerignore 影响、有限入口路径错误、实际选中 context 显式复制已知私有材料给 Agent | 其他目录的同名文件不作实际复制依据；历史 task-root context、变量/多阶段/复杂语法提示复核 |
| artifacts | 合法绝对源路径字符串或 source 对象；对明确 adapter 契约或简单 test.sh 候选参数核对路径覆盖 | Python 源码及复杂脚本未确认执行的路径线索仅提醒；可省略/空数组使用默认 /logs/artifacts，destination 不作容器重映射 |

正式目录禁止 `docker-compose.yaml`、`docker-compose.yml`、`compose.yaml`、`compose.yml`，即使同时存在 Dockerfile 或预构建镜像也不豁免。实际内场 GPU 优先 H20，也接受 L20；CPU 题不增加 GPU。`gpu_types` 含其他候选型号时，只要包含 H20/L20，不因候选列表较长判错，实际内场仍须选 H20/L20。这是依据最新教程对 3.10 旧混合卡型规则的兼容修正，不代表本脚本替代 3.10 全部 21 项质检。

镜像栏只检查声明和来源，不证明镜像已存在或可拉取。有 Dockerfile 但未填平台可用镜像时只提醒，AIDP 实跑前仍须完成镜像准备。CPU 题请使用 `--task-kind cpu`，脚本不靠题意猜测 CPU/GPU 类别。下载包的 31 行对照表分别标注自动检查、部分自动和后续质检，不能解释为 31 项全部自动验收。

## CPU 配置示例

以下镜像标识仅展示格式，必须替换为平台实际可用镜像。专用 Verifier 镜像须预置评分入口、依赖和私有材料；两侧仍为独立 sandbox。

```toml
artifacts = ["/workspace/solution"]

[environment]
docker_image = "hub.byted.org/team/task-solver:v1"
cpus = 16
memory_mb = 65536
gpus = 0

[agent]
timeout_sec = 43200

[verifier]
environment_mode = "separate"
timeout_sec = 3600

[verifier.environment]
docker_image = "hub.byted.org/team/task-verifier:v1"
cpus = 8
memory_mb = 32768
gpus = 0
```

确需 GPU 时，修改对应环境中的下列两项，不重复新增同名 table；不需要 GPU 的一侧仍保持 `gpus = 0`。

```toml
gpus = 1
gpu_types = ["H20", "L20"]
```

复用 Solver 镜像时可不设置专用 Verifier 镜像、也不提供 `tests/Dockerfile`；须按目标 Harbor 版本把 `tests/` 上传到新的 Verifier sandbox，核对所需依赖。显式专用镜像优先于 `tests/Dockerfile`，然后才是复用 Solver 分支。

## 怎么运行

```bash
python3.11 check_package.py 完整包.zip --out 自检报告
python3.11 check_package.py ./完整题包 --out ./自检报告
python3.11 check_package.py ./完整包.tar.gz --out ./自检报告
```

报告目录必须放在待检目录外。可选参数仅有：

```bash
python3.11 check_package.py 完整包.zip --task-kind cpu --out 自检报告
python3.11 check_package.py 完整包.zip --task-kind gpu --out 自检报告
python3.11 check_package.py 完整包.zip --max-files 300000 --max-unpacked-gib 200 --temp-dir /path/to/temp --out 自检报告
python3.11 check_package.py --version
```

`--task-kind` 为 `auto/cpu/gpu`，不按 S1/S2 或是否训练推断设备类别。`--max-files`、`--max-unpacked-gib` 为本次读取/展开上限，不是平台包体限制。可先查目录，最终打包后再查准备上传的压缩包。

## 报告和退出码

- `0`：`PASS` 或 `PASS_WITH_WARNINGS`，没有前置阻断项；`WARN` 不阻断。
- `1`：`FAIL`，存在明确 `ERROR`，修复后再检查。
- `3`：检查未完成，先解决输入读取等问题。

输出 `report.json`、`report.txt`、`report.md` 和 `返修清单.txt`。返修清单仅列 `ERROR`；非阻断提醒看完整报告。格式通过后继续后续 Skill 质检与 AIDP 实跑 Harbor，确认镜像、候选移交、独立评分和结果。返修后重新上传本次检查过的三目录完整包，保留压缩包 SHA-256 便于对应版本；脚本不能证明云端已上传、链接可访问或正式验收通过。
